## 가져오기

1. 서버에 테스트용 DB를 준비한다. 내보낸 파일은 전체 복원 파일이라 같은 이름의 기존 테이블을 교체한다.
2. 현재 코드를 올리고 서버의 `data/dbconfig.php`에 서버 DB 접속 정보와 `G5_TABLE_PREFIX='avo_'`를 설정한다. 로컬 DB 접속 파일을 서버에 덮어쓰지 않는다.
3. phpMyAdmin에서 **대상 테스트 DB를 선택**하고 SQL 파일을 가져온다. DB 이름이 `test`일 필요는 없다.
4. 기존 `data`의 업로드 이미지와 디자인 CSS를 함께 복사하고 `data/cache`, `data/session` 쓰기 권한을 준비한다. 코드 ZIP의 `data` 폴더는 비어 있다.
5. 기존 최고관리자 `test` 계정과 기존 비밀번호로 로그인한다. 새 회원과 임시 비밀번호는 만들지 않았다.
6. 관리자 ‘시스템 설치 / 업데이트’에서 상태를 확인한다. 데이터 파일에는 현재 설치 버전과 inventory InnoDB 전환이 포함되어 있다. 구형 수동 미궁 SQL을 다시 실행하지 않는다.

DB 기준은 MariaDB 10.2.4 이상 또는 MySQL 8.0 이상이다. SQL은 현재 XAMPP의 MariaDB에서 내보내고 다른 이름의 MariaDB DB에 재가져오기까지 검증했다. 서버의 PHP·DB 버전 차이는 서버에서 확인해야 한다. 게시판 스킨이 기존 PHP 짧은 태그를 사용하므로 `short_open_tag=On` 설정도 확인한다.

기존 관리자 디자인 설정에는 `http://localhost/avo_Test/adm/img/logo.png`, `http://localhost/avo_Test/skin/member/basic/img/bak_admin_login_top_pattern.png` 두 주소가 남아 있다. 서버 관리자 디자인 설정에서 서버 주소로 바꾼다. 새 던전·몬스터·레이드 데이터에는 로컬 이미지 주소를 넣지 않았다.

## 설치 화면의 날짜 컬럼 오류 수정

MySQL은 `CURRENT_TIMESTAMP` 같은 식으로 기본값을 지정한 일반 컬럼에 `DEFAULT_GENERATED` 속성을 표시한다. 이전 설치 검사 코드가 이를 계산 컬럼으로 오인해 `field_player.fp_datetime`, `field_log.fl_datetime`을 구조 이상으로 표시할 수 있었다. 로컬 MariaDB의 두 컬럼은 `datetime NOT NULL DEFAULT current_timestamp()`로 정상이며, 현재 코드는 MySQL 표시도 허용한다. 실제 NULL 허용 여부나 컬럼 형식 차이는 계속 검사한다. [MySQL 공식 SHOW COLUMNS 설명](https://dev.mysql.com/doc/refman/8.0/en/show-columns.html)

이미 코드를 올렸다면 `artifacts/installer-datetime-fix-20261005.zip` 안의 `lib/system_installer.lib.php`, `adm/system_install.view.php`를 서버의 같은 경로에 덮어쓰고 설치 화면에서 ‘상태 다시 확인’을 누른다. 전체 코드 ZIP에도 이 수정이 포함되어 있다. 이 수정에는 DB 변경이나 QA 데이터 재생성이 필요하지 않다. 이후에도 구조 이상이 남으면 상세 보기의 현재 NULL 허용·기본값·속성을 확인한다.

하단 ‘전체 설치 상태’는 필드·낚시, 캐릭터 방, 퀘스트, 몬스터를 포함한 모든 기능의 구조와 설치 버전을 검사한다. QA 캐릭터·던전 데이터가 들어 있는지 확인하는 항목은 아니다. 이 문서의 전체 DB 내보내기에는 위에 설명한 QA 데이터가 이미 포함되어 있다.

검증은 MariaDB의 실제 신규 설치·재실행과 MySQL 8 `SHOW FULL COLUMNS` 표시를 재현한 검사로 수행했다. 외부 서버의 실제 DB 구조와 화면은 서버에서 다시 확인한다.

## 시작 위치와 캐릭터

관리자 소유 `[QA] 아린`, `[QA] 바론`, `[QA] 세라`를 재사용했다. 세 캐릭터 모두 `[QA] 중앙 광장`에서 시작한다. 캐릭터 소유권과 관리자 로그인 정보는 유지했다. 기존 QA NPC·장비·재료도 유지했다.

플레이어 HP와 정신을 회복하고, 스킬 12종을 장착했다. 아린은 HP 240·힘 22·정신 60, 바론은 HP 320·힘 16·방어 12·정신 40, 세라는 HP 200·힘 12·정신 100으로 서로 다른 역할을 시험한다. 각 캐릭터에 회복약·정신 회복약·대형 회복약·부활 깃털·해독제·재료를 충분히 보충했다. 몬스터에는 MP와 스킬 재사용 대기시간이 없다. 플레이어 스킬에는 비용과 재사용 대기시간이 적용된다.

한 계정으로 파티를 시험하려면 캐릭터를 전환해 각 캐릭터로 같은 던전에 입장하고 READY를 누른다. 모두 준비되면 출발한다. 전투 중에도 캐릭터를 전환해 각자 행동을 제출하고 턴 종료를 누른다. 서로 다른 회원·권한·동시 브라우저 접속 검증은 이 데이터만으로는 할 수 없다.

## 반복 테스트와 자동 출현

바로 입장할 수 있게 자동 출현 개수는 0, 모집 기간은 87,600시간, 하루 입장 제한은 1,000회로 설정했다. 클리어하거나 닫은 세션은 자동으로 다시 열리지 않는다. 다시 시험하려면 테스트 DB에 내보낸 SQL을 다시 가져오거나, CLI seed로 QA 코스를 재설정한다.

```powershell
python dev/tools/qa_database.py backup --file artifacts/qa-before-rerun.sql
php dev/tools/seed_qa_server.php --apply --backup=artifacts/qa-before-rerun.sql
```

재실행은 QA 진행 기록과 QA 레이드 참가 상태를 초기화한다. 탐험에 보관된 미사용 아이템을 먼저 실제 정산 코드로 돌려주며, 비QA 참가자가 섞인 경우 중단한다. 기존 인벤토리 ID·장비 연결을 유지하고 부족한 수량만 보충한다. MyISAM 정의 테이블도 있으므로 전체 백업을 준비하고 테스트를 멈춘 상태에서 실행한다. 이 Windows 내보내기 도구는 로컬 XAMPP용이며 서버에서는 기존 DB 내보내기 기능을 이용한다.

자동 시간 출현을 시험할 때는 관리자 공통 던전 설정에서 출현 개수 3, 갱신 간격 1시간으로 변경하고 이미 지난 갱신 시각을 입력한 뒤 저장한다. 기존 QA 대기실과 함께 발생할 수 있으니 정해진 코스 테스트 이후에 진행한다.

## 완료한 검증

- 기존 DB 복사본에서 첫 실행·재실행 후 정의 중복과 참조 오류가 없는지 확인.
- 실제 게임 함수로 8개 코스 입장·출발·아이템 보관과 반환, 다수 몬스터·치유 단일 로그·광역 공격, HP·턴 순서, 실제 클리어·보상·재정산 검증.
- 실시간/MMB 광역 공격에서 현재 전투의 살아 있는 적 전부가 피해를 받고 아군·죽은 몬스터·다른 전투는 제외되는지 검증. 총 97개 확인 통과.
- 실제 인증 경로로 맵 입장→대기실 및 던전·몬스터 관리자, MMB·1:1 게시판, 레이드 목록 렌더링 확인.

서버에서는 위 코스를 직접 진행하며 브라우저 표시·서버 설정·여러 요청이 겹치는 상황을 확인한다. 로컬 검사 통과가 서버 환경 검사를 대신하지는 않는다.
